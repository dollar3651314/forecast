## 1. 加密自动生成：场次填 "1:00" 保存失败

### 1.1 现象
Amos 在测试环境：后台"加密自动生成"→ 修改 BTCUSDT 1 小时 → 场次加一行，填 `1:00`。旁边正常显示"北京 09:00"；点"确认执行"后报"操作没有成功 / 提交的内容有误：场次格式不正确"。填 `01:00` 能成功。和"只能填当前时间以后的场次"无关（后端没有这条规则）。

### 1.2 根因【实际执行：先在测试里复现】
前端和后端对"一个时刻"的读法不一样：
- 后端 `AutogenService.slot` 要求严格的 `\d{2}:\d{2}`（两位小时），`1:00` 不匹配 → 字段错误 `slots[1]:invalid`。
- 后台前端 `utils/market.ts` 的 `beijing()` 用 `split(':')` 再 `Number()`，`1:00` 读成 1 点 → 显示"北京 09:00"，看起来是合法的。
- 错误显示 `utils/errors.ts` 把 `slots[1]` 去掉下标再查翻译，只剩"场次格式不正确"，看不出是哪一行、错在哪。
- 复现：把新的集成测试 `CryptoAutogenTest.场次宽松写法_1点写成1冒号00也能保存_逐行报错_S12c` 放在**修复前**的代码上跑，`api.update(... "1:00" ...)` 抛 `ValidationException`（和测试环境一样）【实际执行】。前端"`1:00` 显示北京 09:00"在旧代码里一眼可见（`beijing('1:00')` = `09:00`）【代码走查】。

### 1.3 修复
同一套规则写在两处，后端为准、前端只是提前提示：

| 项 | 规则 |
|---|---|
| 能接受的写法 | `1:00`、`1:0`、`01:00`、`1`、`01`、两边带空格（含全角空格、不换行空格）、全角冒号 `1：00`、冒号两边带空格 `1 : 00` → 都是 `01:00`；`9:5` 是 `09:05`；星期部分 `13:00@ 7 , 6` → `13:00@6,7` |
| 不变的规则 | 时 0～23、分 0～59；1 小时只能整点；15 分钟要是 15 的倍数；同一时刻不能重复 |
| 规范化的地方 | 后端保存时（`AutogenService.parseSlot` → `format`，库里一律是 `HH:mm`）；后台前端**失焦时**（`SlotEditor` 的 `onBlur` → `normalizeSlot`）和**点"确认执行"时**（`readyInput`） |
| 错误码（前后端一致） | `required`（空行）、`timeFormat`（看不懂，例如 `abc`、`1:`、`100`、`1.00`）、`outOfRange`（`24:00`、`12:60`）、`invalidDays`（星期不对）、`hourOnly`、`quarterOnly`、`duplicate`。原来的 `invalid`、`notAligned` 不再用于场次 |
| 报错长什么样 | 行下面红字："第 3 行：1 小时的场次只能是整点（例如 01:00）"，输入框标红；弹窗：`提交的内容有误：场次第 3 行：1 小时的场次只能是整点（例如 01:00）`。`errors.ts` 对所有 `名字[n]` 形式的字段都按"第 n+1 行"显示（也适用于裁决台的 `evidenceUrls[n]`） |
| 北京时间 | `beijing()`、`beijingNextDay()` 改用同一个解析函数：后端不认的写法显示"—"，不会再"前端显示正常、后端拒绝" |

- 后端：`backend/src/main/java/com/forecast/app/market/autogen/AutogenService.java`（`parseSlot`、`SlotParse`、`slot` 改成调用 `parseSlot`）【实际执行】
- 后台前端：`web/admin/src/utils/market.ts`（`normalizeSlotTime`、`normalizeSlot`、`slotProblems`、`beijing`）、`web/admin/src/pages/markets/AutogenPage.tsx`（`SlotEditor` 失焦规范化、逐行标红、保存前检查）、`web/admin/src/utils/errors.ts`（"第 n 行"）、翻译 `apiFieldCode.*`、`errors.fieldRowProblem`、`ag.slotRowProblem`；模拟层 `mocks/fc.ts` 用同一个 `slotProblems`【实际执行】
- 空白字符集两边写死成同一组（空格、Tab、回车换行、U+00A0、U+3000），不用 Java 的 `strip()` / `\s` 和 JS 的 `trim()` / `\s`（两种语言对 Unicode 空白的理解不一样）；数字只认半角 0～9（`１:00` 两边都报 `timeFormat`）【实际执行：两边同一组用例】

### 1.4 研发的决定
| 编号 | 决定 | 理由 |
|---|---|---|
| D-254 | 分钟写一位按数值读（`9:5` = 09:05，不是 09:50） | 和 `1:0` = 01:00 一致；1 小时、15 分钟两种周期下 `x:5` 都会被对齐规则拒绝，不会悄悄存错 |
| D-255 | 一行同时"不整点"又"重复"时只报不整点 | 和改之前一样一行一个错误；改对以后再看重复 |
| D-256 | 前端错误当场显示（不等失焦） | 任务要求"保存前就把这一行标红"；失焦后已规范化，输入过程中的 `1:` 短暂标红可以接受 |

## 2. 其他时间输入的检查【代码走查】
| 位置 | 输入方式 | 结论 |
|---|---|---|
| 市场编辑的开放 / 截止 / 事件开始 / 结束（`MarketEditPage`）、提前截止（`MarketDetailPage`）、裁决台实际开赛时间（`ResolveDeskPage`） | 浏览器原生 `datetime-local`，值固定是 `YYYY-MM-DDTHH:mm`，`fromInput` 严格校验 | 不能自由输入，没有同样的问题 |
| 内容中心经济日历的发布时间（`ContentEventsPage`） | antd `DatePicker`（`showTime`） | 选择器，没有同样的问题 |
| 归集设置的自动归集时刻（`SweepSettingsPage`） | `InputNumber` 0～23 | 数字输入，没有同样的问题 |
| 今日场次（市场编辑"列入今日场次"、详情页加入 / 移出） | 勾选 / 按钮，时间来自市场本身 | 没有时刻输入 |
| 开赛提醒（客户端 #23） | 按钮，时间来自赛程 | 没有时刻输入；客户端 `web/client` 里没有 `HH:mm` 输入框 |
| 体育（`SportsPage`） | 只有备源编号和分界线 | 没有时刻输入 |
| 参数设置（`ParamsPage`） | 小时 / 分钟数 | 数字，不是时刻 |

结论：后台只有"加密自动生成的场次"一处是自由输入的 `HH:mm`，这次已修。
